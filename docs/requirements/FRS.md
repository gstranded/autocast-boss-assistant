## FR-01 岗位筛选规则引擎（P0）

### FR-01-1 分字段过滤

系统必须支持以下字段独立配置包含/排除规则：

1. 职位名称
2. 公司名称
3. 职位描述（JD）
4. 工作地点

### FR-01-2 AND / OR / NOT 语义

对文本类规则，每个字段至少支持：

| 规则类型 | 语义 |
|----------|------|
| 包含任意（OR） | 命中任一关键词即满足该条件组 |
| 必须同时包含（AND） | 所有关键词均需命中 |
| 排除任意（NOT） | 命中任一排除词则整岗淘汰 |

组合逻辑（同一字段内）：

```text
(OR组) AND (AND组) AND NOT (NOT组)
```

跨字段默认 **AND**（全部字段条件都满足才通过）。

### FR-01-3 地点匹配模式

1. **精确匹配**：城市值完全相等（如仅“广州”）
2. **包含匹配**：文本包含（如“天河”匹配“广州·天河”）

### FR-01-4 扩展筛选维度（P0 建议集）

| 维度 | 说明 |
|------|------|
| 薪资最低/最高 | 解析岗位薪资区间并比较 |
| 工作经验 | 如 不限/1-3/3-5 等 |
| 学历要求 | 大专/本科/硕士等 |
| 公司规模 | 如 0-20 / 100-499 |
| 融资阶段 | 如 A轮/已上市（若页面可得） |
| 行业 | 若页面可得 |
| HR 活跃时间 | 今日活跃/3日内/本周等 |
| 是否猎头 | 识别并可选排除 |
| 是否外包/驻场 | 关键词 + 可选规则 |
| 是否校招/实习 | 可选过滤 |
| 职位发布时间 | 优先新岗位 |
| JD 关键词福利项 | 如双休等（可选） |

### FR-01-5 黑白名单

1. 公司名称黑名单
2. 公司名称白名单（启用时仅允许白名单，或白名单加权，V1 建议：白名单开启则仅投白名单）
3. 手动标记加入
4. 导入/导出
5. 命中后写明原因

### FR-01-6 可解释输出

每个被过滤岗位必须产出：

- `decision`: pass / reject
- `reasonCodes[]`
- `reasonTexts[]`（中文可读）

## FR-02 投递前预览（P0）

### FR-02-1 扫描预览

在正式发起沟通前，系统必须支持扫描当前列表（含滚动加载策略）并展示汇总：

```text
扫描岗位：N1
符合规则：N2
已沟通：N3
关键词不匹配：N4
命中排除词：N5
地点不匹配：N6
HR不活跃：N7
信息缺失：N8
其他跳过：N9
```

### FR-02-2 明细列表

用户可查看每个岗位的：

- 职位 / 公司 / 地点 / 薪资
- 决策：将投递 / 将跳过
- 原因列表
- （P1）匹配分与风险项

### FR-02-3 确认门禁

1. 默认必须经用户确认后才进入自动发送。
2. 提供“重新扫描”。
3. 允许在预览中手动取消个别将投递岗位（P0 建议支持）。

### FR-02-4 风险提示

当通过率异常（如通过率 > 80% 或 < 5%）时给出提示，建议用户检查规则。

## FR-03 多段消息发送（P0）

### FR-03-1 招呼来源控制

1. 读取并展示 BOSS 账号自动招呼的真实开关、当前模板和同步时间。
2. 推荐关闭 BOSS 自动招呼，由插件统一发送；修改账号全局开关前必须二次确认，修改后必须回读校验。
3. 支持在插件中编辑 BOSS 当前话术：内置模板创建自定义副本，自定义模板原地编辑；保存后设为当前并回读校验，最多 100 字。
4. 插件消息提供总开关；关闭后不发送任何插件文字。
5. 每段消息显式标记为 `greeting`（招呼）或 `supplement`（补充）。旧模板自动迁移：第一段为招呼，其余段为补充。

### FR-03-2 自动招呼证据与发送流程

1. 点击“立即沟通”时监听创建沟通接口的返回，优先读取 `showGreeting` 和实际 `greeting` 文本。
2. 接口回执缺失时读取已同步的 BOSS 账号开关。
3. 两者都无法确认时，以进入会话后的本人消息作为基线，等待新的本人消息气泡。
4. 确认平台已发招呼：跳过所有 `greeting` 段，只按顺序发送 `supplement` 段。
5. 确认平台未发招呼：按顺序发送全部启用段。
6. 仍为未知且模板包含招呼段：暂停任务并给出明确原因，不得冒险发送。
7. 面板实时预览最终发送顺序，标明每段来源为 BOSS 或插件。

### FR-03-3 旧版相似度兼容

标准化至少包括：

- 去除多余空白与换行
- 统一中英文标点
- 去除表情符号
- 去除可选前缀：您好/你好/Hi/Hello 等

相似度：

- V1 可采用规范化后包含关系 + 编辑距离/Jaccard 等轻量算法
- 默认阈值建议 0.85，可配置
- 不得仅用全等比较。相似度仅用于旧配置兼容，不能覆盖平台明确回执。

### FR-03-4 消息配置能力

- 多段文本
- 拖拽排序
- 单段启用/停用
- 段间发送间隔
- 最大发送段数
- 发送前预览（变量已渲染）
- 字数提示
- 模板变量：

```text
{HR称呼}
{职位名称}
{公司名称}
{匹配技能}
{工作城市}
```

### FR-03-5 变量安全

1. 变量缺失或渲染失败时：
   - 策略可选：**阻止发送该段**（默认）或 **回退无变量模板**
2. 禁止发送包含未解析 `{...}` 占位符的内容

### FR-03-6 发送状态机

每个“岗位沟通实例”具备状态：

```text
NOT_STARTED
COMMUNICATION_CREATED
NATIVE_GREETING_DETECTED
TEXT_SEGMENT_1_SENT
TEXT_SEGMENT_2_SENT
...
IMAGE_RESUME_SENT
COMPLETED
FAILED
PAUSED
```

转移规则：

- 只允许向前推进或进入 FAILED/PAUSED
- 重试时从最近未完成步骤继续
- 已到达的 `*_SENT` 不得因重试再次执行

### FR-03-7 幂等键

每段消息发送意图使用：

```text
jobId + bossId + templateVersion + segmentIndex
```

同一幂等键在成功后不得重复发送。

## FR-04 图片简历（P0）

### FR-04-1 独立开关

```text
自动发送图片简历  [on/off]
```

### FR-04-2 发送时机

| 时机 | 默认 |
|------|------|
| HR 请求简历后发送 | 推荐默认 |
| 首次沟通文本完成后立即发送 | 可选，默认关 |
| 仅手动点击发送 | 可选 |

首次沟通后立即发送由用户显式开启。

### FR-04-3 图片简历

支持：

- 多图上传、预览、排序、删除
- 格式校验（如 png/jpg/jpeg/webp）
- 大小校验与过大压缩提示
- **串行按序发送**（禁止并发导致乱序）
- 成功状态、失败重试、防重复

### FR-04-4 存储与授权

BOSS 自带“发简历”按钮受双向回复门禁限制，不纳入自动投递。平台简历由用户在招聘者回复后手动发送。

1. 首次必须由用户主动选择文件
2. 可在扩展本地存储或 IndexedDB 保存以复用
3. 默认不上传到开发者服务器
4. 用户可删除本地简历数据

## FR-05 多简历配置与规则绑定（P0）

### FR-05-1 多求职档案

用户可创建多个简历档案，例如：

```text
Java 后端简历
AI 算法简历
Agent 应用简历
```

每个档案包含：图片简历集合、附件简历、备注名。

### FR-05-2 绑定规则

支持按职位名称/JD 关键词路由：

```text
包含 算法|模型|LLM → AI 算法简历
包含 Java|Spring → Java 后端简历
包含 Agent|RAG → Agent 应用简历
```

### FR-05-3 冲突与回退

1. 多规则命中：按优先级（可排序）选择最高优先级
2. 无命中：使用默认档案
3. 档案缺失文件：记录失败原因并跳过简历步骤（消息步骤可已完成）

---

## FR-06 防重复与幂等（P0）

### FR-06-1 去重维度

至少识别：

1. 相同职位 ID
2. 相同 HR（bossId）
3. 相同公司 + 职位名（弱维度，防 ID 变化）
4. 已存在聊天会话
5. 本次任务已处理
6. 历史任务已处理
7. 已发送简历
8. 已发送某段消息

### FR-06-2 用户可配置策略

```text
同一职位永不重复
同一 HR N 天内不重复（默认 30）
同一公司每天最多投递 M 个岗位（默认 3）
职位重新发布后允许再次投递（可选）
```

### FR-06-3 幂等与恢复

见 FR-03-6/7；任务恢复不得破坏幂等。

## FR-07 任务控制与异常恢复（P0）

### FR-07-1 控制操作

必须支持：

- 开始
- 暂停
- 继续
- 停止
- 跳过当前岗位
- 失败重试（当前步骤）
- 页面刷新后恢复
- 浏览器崩溃后尽可能恢复（依赖本地持久化）

### FR-07-2 运行时展示

显示：

- 当前岗位
- 当前步骤（状态机状态）
- 已处理 / 成功 / 跳过 / 失败计数
- 剩余限额（本次/每日）

### FR-07-3 持久化检查点

至少持久化：

- taskId、方案快照、进度索引
- 每岗位状态与已发送幂等键集合
- 暂停/失败原因

## FR-08 速率与数量控制（P0）

用户可见可配，并提供安全默认：

| 项 | 建议默认 |
|----|----------|
| 本次最多沟通 | 30 |
| 每日最多沟通 | 80 |
| 同一公司最多 | 3 |
| 消息发送间隔 | 可配，如 1.5~3s 随机 |
| 岗位处理间隔 | 可配 |
| 连续失败自动暂停 | 3 次 |

达到限额时任务暂停或结束，并明确提示原因。

**禁止**将“绕过平台风控”描述为产品功能。

---

## FR-09 实时日志与跳过原因（P0）

### FR-09-1 日志级别

info / warn / error

### FR-09-2 原因必须具体

示例：

```text
跳过：职位名称命中排除词“外包”
跳过：工作地点“佛山”不符合广州/深圳
跳过：该 HR 7 天内已沟通
失败：聊天窗口未加载
失败：图片简历上传超时
```

### FR-09-3 导出

支持导出当前/历史任务日志（P0 可用文本或 JSON）。

日志必须按数值时间戳稳定排序；面板默认最新在上，复制文本按时间正序，并显示月日与时分秒，避免跨天记录看似乱序。

---

## FR-10 配置本地保存与导入导出（P0）

### FR-10-1 持久化对象

- 筛选规则
- 消息模板
- 黑白名单
- 简历配置（含本地文件引用/二进制）
- 投递记录
- 任务设置与限额

### FR-10-2 导入导出

- 导出 JSON（简历二进制可选用独立打包策略；V1 可导出元数据 + 提醒用户重新选择文件，或导出含 base64 的完整包）
- 导入时版本兼容校验
- 防止插件升级丢失配置

### FR-10-3 清理

- 清理过期投递记录
- 清理日志
- 一键清除敏感数据

## FR-11 自动投递主循环（P0）

系统应支持在用户确认后：

1. 滚动加载职位
2. 规则过滤
3. 防重复与限流检查
4. 点击立即沟通
5. 发送消息段落
6. 按策略发送简历
7. 进入下一岗位
8. 更新计数与日志

## FR-20 多套求职方案（P1）

一套方案包含：筛选、自我介绍、图片简历、投递数量、黑名单、简历版本等。
支持创建、切换、复制、重命名、删除。

## FR-21 投递漏斗与统计（P1）

统计：

```text

符合规则数
发起沟通数
已读数
HR回复数
简历请求数
面试邀请数
拒绝数
```

维度：关键词、城市、公司、简历版本、消息模板、日期。

## FR-22 规则命中解释增强（P1）

展示匹配分、通过原因、风险项（如 JD 含“客户现场”）。

## FR-23 语义匹配（P1/P2）

1. 关键词高召回
2. 简历-JD 向量/模型二次排序
3. 展示匹配理由
4. 用户阈值确认

## FR-24 AI 回复建议（P1）

默认流程：

```text
生成回复 → 用户确认 → 发送
```

不得默认全自动发送涉及薪资、到岗、学历、经历等关键事实的回复。

---

## FR-25 跟进提醒（P1）

- HR 已读 24h 未回复
- HR 请求简历未发送
- 面试邀请未确认
- 3 天后跟进提醒

V1 不做自动追问；V2 可一键发送预设跟进语。

## 5. 关键验收用例（节选）

| 编号 | 场景 | 期望 |
|------|------|------|
| AC-01 | 预览中规则错误导致大量排除 | 显示原因；未确认不发送 |
| AC-02 | BOSS 已发原生打招呼且与第一段相似 | 跳过第一段，只发后续 |
| AC-03 | 刷新页面后任务继续 | 不重发已发送段落/简历 |
| AC-04 | 同 jobId 再次扫描 | 防重复跳过并写原因 |
| AC-05 | 图片三页简历 | 按 1→2→3 顺序发送 |
| AC-06 | 变量 `{职位名称}` 缺失 | 不发送裸占位符 |
| AC-07 | 连续失败 3 次 | 自动暂停任务 |
| AC-08 | 达到本次上限 | 停止沟通并提示 |
| AC-09 | 命中公司黑名单 | 跳过并显示公司黑名单原因 |
| AC-10 | 导出配置后重装导入 | 规则与模板恢复可用 |
