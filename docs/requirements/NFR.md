# 非功能需求（NFR）

| 字段 | 内容 |
|------|------|
| 文档版本 | v1.0 |
| 日期 | 2026-07-29 |
| 状态 | Draft |

---

## NFR-01 性能

1. 预览扫描单页职位解析应在可交互时间内完成；滚动加载时保持 UI 可取消。
2. 消息段间间隔遵循用户配置，不因内部计算显著漂移（误差 < 20%）。
3. 本地查询历史去重（万级记录内）应在 100ms 量级完成（常规笔记本环境，目标值，可按实现调整）。
4. 大图片简历保存与读取不得冻结侧边栏超过 1s；必要时异步化并给出进度。

---

## NFR-02 可靠性

1. 任意单岗位失败不得导致整个扩展崩溃。
2. 连续失败达到阈值必须自动暂停。
3. 任务检查点持久化成功后，刷新页面可恢复。
4. 幂等层保证“成功发送”的段落/简历在恢复后不重发。
5. 关键写操作（历史、幂等键）应尽量原子更新。

---

## NFR-03 安全与隐私

1. **本地优先**：配置、投递记录、简历默认仅存本地扩展存储/IndexedDB。
2. 不默认上传简历、聊天内容到自有服务器。
3. 导出文件可能含敏感信息，导出时提示用户妥善保存。
4. 最小权限原则：仅申请功能所需 host 权限与存储权限。
5. 不提供、不文档化任何“绕过验证码/风控”的实现路径。
6. XSS：若注入页面 DOM，需注意不要执行不可信 HTML 为脚本。

---

## NFR-04 可观察性

1. 每个岗位处理链路可在日志中还原关键步骤。
2. 所有系统跳过/失败具备稳定 `reasonCode`。
3. 版本号、任务 ID 在日志头部可追踪。

---

## NFR-05 可用性

1. 主流程（配置 → 预览 → 开始 → 暂停/停止）不超过 3 个主要界面层级。
2. 危险操作（清空数据、大量立即发送简历）需要确认。
3. 默认值应保守（限额、间隔、简历不立即双发）。
4. 关键错误提示使用业务语言，不只显示技术堆栈。

---

## NFR-06 兼容性

1. 目标浏览器：Chromium 内核（Chrome / Edge）最新两个大版本。
2. 目标站点：BOSS 直聘 Web 求职端核心流程页面。
3. Manifest 版本：建议 MV3（最终以工程选型 ADR 为准，若后续补充）。
4. 页面结构变更时，选择器失败应可检测并暂停，而非盲点。

---

## NFR-07 可维护性

1. 规则引擎、去重、发送状态机、DOM 适配层分离。
2. 关键策略以配置/规则数据驱动，避免硬编码散落。
3. 需求与 ADR 同步更新。

---

## NFR-08 合规与产品边界

1. 功能文案避免鼓吹违规批量骚扰。
2. 强调用户主动配置与确认。
3. 频率限制对用户可见。
4. 尊重平台对消息数量与行为的限制提示，检测到限制时应停止并解释。

---

## NFR-09 数据保留

| 数据 | 默认策略 |
|------|----------|
| 投递历史 | 本地保留，支持按天数清理（如 90 天） |
| 日志 | 可设上限条数/天数 |
| 简历二进制 | 用户管理；卸载时可随扩展清除 |
| 幂等键 | 随历史保留策略或至少保留 N 天 |

---

## NFR-10 测试要求（V1）

1. 规则引擎纯函数单测（AND/OR/NOT、地点精确/包含）。
2. 文本标准化与相似度单测。
3. 状态机转移与幂等单测。
4. 预览汇总计数单测。
5. 关键路径手工验收：沟通、去重、刷新恢复、简历顺序。
