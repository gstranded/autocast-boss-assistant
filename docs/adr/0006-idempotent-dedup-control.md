# ADR-0006：三级防重复与幂等控制

- 状态：Accepted
- 日期：2026-07-29
- 决策者：产品 / 研发
- 关联：FR-06, FR-03, FR-07, NFR-02

## 背景

重复沟通会浪费每日限额、打扰同一 HR、降低账号健康度，并损害求职体验。仅按职位标题去重不足，因为存在职位重新发布、同一 HR 多岗位、同一公司多 JD 等情况。

同时，任务重试与页面刷新若无幂等，会造成同一段落/简历重复发送。

## 决策

### 1. 三级防重复（用户可配）

| 层级 | 策略示例 |
|------|----------|
| 职位 | 同一 jobId 永不重复（默认） |
| HR | 同一 bossId N 天内不重复（默认 30 天） |
| 公司 | 同一公司每天最多 M 个岗位（默认 3） |

补充弱键：公司名+职位名；已存在会话；本任务已处理。

### 2. 发送层幂等

消息段与简历发送成功后写入幂等记录，恢复时跳过。

### 3. 可解释

所有去重拦截必须写原因，不得静默跳过。

## 备选方案

1. **只按 jobId**：实现简单，漏拦截多。
2. **全局永久任意相似职位不投**：过严，伤召回。
3. **服务端去重**：与本地优先冲突，V1 不做。

## 后果

### 正面

- 降低重复打扰
- 支持安全重试

### 负面 / 风险

- 历史数据膨胀需清理策略
- ID 缺失时弱键可能误伤

## 后续动作

- 设置页暴露 N/M 参数
- 历史清理与导出
