# ADR-0010：任务控制与异常恢复机制

- 状态：Accepted
- 日期：2026-07-29
- 决策者：产品 / 研发
- 关联：FR-07, FR-09, NFR-02, ADR-0003, ADR-0006

## 背景

海投任务跨多个页面状态与长时间运行，用户会暂停、刷新、遇到 DOM 超时、上传失败等。没有统一任务控制器时，常见问题是：

- 无法停止
- 刷新后从头重复
- 失败后盲跑
- 不知道卡在哪一步

## 决策

1. 任务一等公民化：具备生命周期 `created/running/paused/stopped/completed/failed`。
2. 控制操作完整：开始、暂停、继续、停止、跳过当前、重试当前步骤。
3. **检查点持久化**：任务进度、每岗状态机状态、幂等键集合。
4. 页面刷新后恢复；连续失败达阈值自动暂停。
5. UI 展示当前步骤与计数；日志记录原因码。
6. 执行基于预览确认后的岗位快照，避免与实时列表无协同地狂奔。

## 备选方案

1. **无恢复，刷新即丢**：实现简单，不可用。
2. **只内存状态机**：无法跨刷新。
3. **完全依赖远程任务队列**：与本地优先和扩展形态不符。

## 后果

### 正面

- 符合“任务随时可控”
- 与幂等/去重形成闭环

### 负面 / 风险

- 检查点设计有一定复杂度
- 站点改版导致步骤超时需良好降级

## 后续动作

- 定义标准 reasonCode 表
- 崩溃恢复的手工验收清单
