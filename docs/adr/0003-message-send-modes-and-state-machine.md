# ADR-0003：多段消息发送模式与状态机

- 状态：Accepted
- 日期：2026-07-29
- 更新：2026-08-21（v1.7.7 以平台回执 + 消息角色替代手动模式）
- 决策者：产品 / 研发
- 关联：FR-03, FR-06, ADR-0006

## 背景

用户需要多段自我介绍，但 BOSS 可能自动发送原生打招呼语。若插件再发高度相似的第一段，会造成重复、不专业，甚至影响回复率。

仅提供“多个输入框依次发送”不足以解决问题，必须处理：

- 与原生打招呼去重
- 刷新/重试不重发
- 段顺序与间隔

## 决策

### 1. 平台回执 + 消息角色

- 创建沟通后优先使用平台 `showGreeting` / `greeting` 回执；回执缺失时使用账号开关，再以“进入会话后的新本人消息”兜底。
- 模板段显式分为 `greeting` 与 `supplement`。确认平台已发时只跳过招呼段，不影响补充段。
- 状态仍未知且存在招呼段时安全暂停。旧版三种模式和相似度仅保留为配置兼容，不再由用户手工选择。
- 面板可以同步和修改 BOSS 自动招呼账号开关，写入前二次确认，写入后回读校验。

### 2. 标准化 + 相似度兼容

不得只做字符串全等；旧配置回退路径先标准化再比相似度，但不得覆盖平台明确回执。

### 3. 显式状态机

```text
NOT_STARTED → COMMUNICATION_CREATED → NATIVE_GREETING_DETECTED?
→ TEXT_SEGMENT_n_SENT → IMAGE/PLATFORM_RESUME_SENT → COMPLETED
可进入 PAUSED / FAILED，恢复时按检查点续跑
```

### 4. 幂等键

`jobId + bossId + templateVersion + segmentIndex`

## 备选方案

1. **总是跳过第一段**：简单，但用户关闭原生时会缺招呼。
2. **总是全发**：重复率高，体验差。
3. **无状态机仅队列**：难处理中断恢复与幂等。

## 后果

### 正面

- 显著降低重复自我介绍
- 恢复路径清晰

### 负面 / 风险

- 聊天 DOM 读取可能因页面改版失败
- 相似度阈值需可配并给默认值

## 后续动作

- 默认阈值 0.85
- 变量渲染失败默认阻止发送
- 为状态机写单测
