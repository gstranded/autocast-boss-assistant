# ADR-0003：多段消息发送模式与状态机

- 状态：Accepted
- 日期：2026-07-29
- 决策者：产品 / 研发
- 关联：FR-03, FR-06, ADR-0006

## 背景

用户需要多段自我介绍，但 BOSS 可能自动发送原生打招呼语。若插件再发高度相似的第一段，会造成重复、不专业，甚至影响回复率。

仅提供“多个输入框依次发送”不足以解决问题，必须处理：

- 与原生打招呼去重
- 刷新/重试不重发
- 段顺序与间隔

## 决策

### 1. 三种发送模式

| 模式 | 说明 |
|------|------|
| A native_plus | 使用原生打招呼，插件只发补充段 |
| B plugin_only | 关闭原生后完全由插件发送 |
| C auto_detect | **默认**：检测已发本人消息，相似则跳过第一段 |

### 2. 标准化 + 相似度去重

不得只做字符串全等；先标准化再比相似度。

### 3. 显式状态机

```text
NOT_STARTED → COMMUNICATION_CREATED → NATIVE_GREETING_DETECTED?
→ TEXT_SEGMENT_n_SENT → IMAGE/PLATFORM_RESUME_SENT → COMPLETED
可进入 PAUSED / FAILED，恢复时按检查点续跑
```

### 4. 幂等键

`jobId + bossId + templateVersion + segmentIndex`

## 备选方案

1. **总是跳过第一段**：简单，但用户关闭原生时会缺招呼。
2. **总是全发**：重复率高，体验差。
3. **无状态机仅队列**：难处理中断恢复与幂等。

## 后果

### 正面

- 显著降低重复自我介绍
- 恢复路径清晰

### 负面 / 风险

- 聊天 DOM 读取可能因页面改版失败
- 相似度阈值需可配并给默认值

## 后续动作

- 默认阈值 0.85
- 变量渲染失败默认阻止发送
- 为状态机写单测
