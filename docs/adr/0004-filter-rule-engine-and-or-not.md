# ADR-0004：筛选规则引擎采用 AND/OR/NOT 分字段语义

- 状态：Accepted
- 日期：2026-07-29
- 决策者：产品 / 研发
- 关联：FR-01, FR-02, FR-22

## 背景

“一个关键词输入框”无法表达真实求职意图。例如用户要：

- 职位可以是 Java 或 Go
- 但必须与 Agent/大模型相关
- 并排除外包/驻场

且“外包”可能出现在公司名、职位名或 JD 中，混在一个字段会降低可解释性。

## 决策

1. **分字段配置**：职位名称、公司名称、JD、地点。
2. 每字段支持 **OR / AND / NOT** 规则组。
3. 跨字段默认 AND。
4. 地点支持精确匹配与包含匹配。
5. 每次决策输出 `reasonCodes` + 可读文案，供预览与日志使用。
6. V1 以确定性规则为主，不做语义向量（见 ADR-0009）。

## 备选方案

1. **单一关键词框**：实现快，误投高，不可解释。
2. **完整布尔表达式编辑器**：灵活但学习成本高，V1 不首选。
3. **纯 AI 筛选**：不稳定且 V1 不做。

## 后果

### 正面

- 表达力足够覆盖主流场景
- 与“可解释筛选”差异化一致

### 负面 / 风险

- UI 比单框复杂，需要良好默认与示例

## 后续动作

- UI 提供示例模板（如“广州 AI 岗”）
- 规则引擎纯函数化便于单测
